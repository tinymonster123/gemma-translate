模型不进扩展包

chrome-extension:// 读 ≥1 GiB 会让 Chrome 主进程 EXC_BREAKPOINT。实测：1000 MiB 正常，1024 MiB（2³⁰）崩。

推理不进 Service Worker

HTML 规范禁止 SW 里动态 import()，而 ORT 的 WebGPU EP 依赖它。唯一可用的常驻后台是 offscreen document。

offscreen 没有 chrome.storage

它只拿到很有限的扩展 API。所以 modelHost 必须由 SW 读出来，再用 config 消息转发进去。

wasm 走扩展包稳定路径

26.9 MB 从 /ort/ 读取，远低于 1 GiB 那条线； 不从 CDN 拉，离线、CSP、网络都可控。
